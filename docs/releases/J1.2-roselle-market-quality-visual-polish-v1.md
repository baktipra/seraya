# J1.2 — Roselle Market-Quality Visual Polish V1

Status: implementation candidate after J1.1 lock

## Purpose

Take the already-correct Roselle guest journey from market-floor completeness to a more premium visual and emotional finish without reopening Seraya's locked invitation architecture.

## Market-quality decisions

- Use the first existing gallery image as an optional Roselle opening portrait. This is presentation reuse of canonical media, not a new portrait field.
- Use the second existing gallery image as an optional story interlude so Roselle gains a second editorial photo moment before the gallery payoff.
- Keep the existing paper/typographic opening as the graceful fallback when no gallery image exists.
- Preserve the J1.1 personal opening ritual, guest greeting, audio gesture, countdown, event utility, gallery, gift, RSVP, Guestbook, and farewell order.
- Reduce duplicate event chrome: when the native schedule utility exists, Roselle visually suppresses the older direct event map link while preserving fallback behavior for incomplete utility events.
- Treat the gallery as Roselle's second emotional peak with deeper contrast, larger image cadence, and a more cinematic mosaic.
- Remove procedural response-step labels from the visual surface while retaining the underlying RSVP/Guestbook order and accessible controls.
- Make the closing a deliberate dark emotional landing and refine the floating Roselle music control to match the invitation.

## Performance and accessibility

- Extend the existing render-safe invitation image component with backward-compatible `fetchPriority` and `loading` controls.
- Opening media is eager/high-priority because it can become Roselle's LCP asset; gallery media remains lazy/low-priority by default.
- Reused opening/story images are decorative in those placements and remain meaningfully described in the canonical gallery.
- Preserve visible focus states, minimum touch targets, reduced-motion handling, and explicit 430px / 390px / 360px quality gates.

## Deliberate non-goals

- No database migration.
- No draft/editor schema expansion.
- No new guest or public route.
- No changes to public/personal authorization or caching boundaries.
- No invented per-person portrait field.
- No invented standalone wedding-film field.
- No Aruna or Laras art-direction changes.
- No production deployment in this implementation pass.
