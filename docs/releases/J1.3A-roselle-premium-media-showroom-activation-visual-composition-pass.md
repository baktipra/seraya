# SERAYA — J1.3A Roselle Premium Media Showroom Activation & Visual Composition Pass

## Status

Implemented as a showroom-only activation layer for production visual proof. No database, owner workflow, published snapshot, guest-link, or delivery behavior changes are included in this milestone.

## Goal

Prove the J1.3 premium guest media foundation on the real Roselle renderer with the canonical Kirana & Arga showroom instead of relying on gallery fallback.

The proof must visibly exercise:

- dedicated cover media;
- portrait media for each member of the couple;
- per-person social identity;
- dedicated story media;
- standalone Wedding Film;
- responsive composition at the 430 / 390 / 360 px mobile floor;
- unchanged generic versus personal invitation semantics.

## Implementation

### Roselle showroom activation

`roselle-premium-showroom.ts` decorates only the Roselle canonical showroom view model. Aruna and Laras receive the original canonical view model unchanged.

The activation uses existing local Kirana & Arga showroom assets for:

- cover;
- Kirana portrait proof;
- Arga portrait proof;
- story media.

The two individual portrait proofs intentionally reuse the existing editorial couple portrait and are separated only by showroom-scoped left/right crop composition. This crop behavior does not apply to customer-uploaded portrait media.

### Wedding Film

The showroom enables one YouTube Wedding Film using the privacy-enhanced `youtube-nocookie.com` embed surface already supported by J1.3.

The demo film is a Creative Commons wedding reference and is explicitly attributed in the showroom caption. It is demonstration media only; production customer invitations continue to use the couple's configured YouTube film.

No autoplay, uploaded-video pipeline, transcoding, or new storage behavior is introduced.

### Visual composition

Roselle-specific showroom CSS now:

- lets the canonical premium cover `<img>` own the opening visual instead of a Roselle background-image override;
- crops the shared editorial portrait toward Kirana and Arga independently;
- tunes story image positioning;
- constrains the film frame;
- preserves 44 px social-link targets from the J1.3 premium media layer;
- adds explicit 430, 390, and 360 px showroom gates.

Legacy showroom image treatment remains available to Aruna and Laras and the gallery demo remains unchanged.

## Privacy and architecture invariants

J1.3A is deliberately outside owner/published data flow:

- no Supabase migration;
- no schema change;
- no media upload API change;
- no public media authorization change;
- no guest identity or token data;
- no RSVP or Guestbook persistence;
- generic showroom remains generic;
- personal showroom continues to use non-persisting simulated personal slots.

## Release gate

J1.3A is ready for acceptance only after:

1. production build and TypeScript/static generation succeed;
2. generic and personal Roselle showroom routes return 200;
3. production HTML proves `featured-cover`, two portraits, per-person socials, story media, and Wedding Film;
4. generic/personal response boundaries remain intact;
5. runtime error smoke is clean;
6. live browser visual inspection is completed where the execution environment permits access.

This milestone does not by itself lock J1.3 or J1.3A. User acceptance remains the final governance gate.
