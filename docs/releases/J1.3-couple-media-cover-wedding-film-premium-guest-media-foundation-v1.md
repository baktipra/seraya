# SERAYA — J1.3 Couple Media, Cover, Wedding Film & Premium Guest Media Foundation V1

Status: Implementation candidate

## Goal

Move Roselle from gallery-derived wedding media to first-class canonical guest media without weakening the published snapshot, guest privacy, or private Storage boundaries.

## Product scope

J1.3 adds the content primitives that were missing during J1.1/J1.2:

- dedicated cover image;
- dedicated portrait for each member of the couple;
- dedicated story image;
- per-person Instagram, TikTok, and website links;
- standalone YouTube Wedding Film;
- owner-facing media management inside the existing Invitation Studio Media workspace;
- Roselle-native rendering for these primitives.

Gallery, invitation audio, livestream, RSVP, Guestbook, multi-event scheduling, personal greeting, and couple-level identity remain separate existing capabilities.

## Data contract

The invitation draft remains schema version 1. `premiumMedia` is additive and defaulted so legacy drafts and published snapshots continue to parse without data rewrites.

The canonical draft shape contains:

- `coverImageId`;
- `personOne.imageId` + per-person social links;
- `personTwo.imageId` + per-person social links;
- `storyImageId`;
- `weddingFilm.enabled`, `heading`, `caption`, and YouTube `url`.

Wedding Film is URL-based in J1.3. There is no uploaded-video object, transcoding pipeline, autoplay, or new video table.

## Media architecture

M0024 adds `invitation_image` as a private `media_assets.media_kind` while keeping the existing private `invitation-media` Storage bucket.

Four image roles are supported:

- `cover`;
- `person_one`;
- `person_two`;
- `story`.

Owner upload follows the existing signed-upload pattern:

1. authenticated reserve;
2. direct upload to a short-lived signed Storage URL;
3. server-side re-download and magic-byte validation;
4. atomic finalization into one premium media role.

Premium images are never appended to `gallery.imageIds`.

## Publication and privacy boundary

M0024 validates premium image IDs when a published snapshot is inserted. Every referenced premium image must:

- belong to the same project;
- be `invitation_image`;
- be ready;
- not be deleted.

The public media proxy exposes a premium binary only when the asset is referenced by the current published snapshot of a currently published project.

Generic and personal routes resolve the same public-safe snapshot media. Guest names, guest tokens, RSVP state, delivery data, and owner session state never enter `InvitationViewModel`.

M0025 protects current published snapshots during draft edits: replacing or removing a premium role does not delete an asset that is still referenced by the current published snapshot. The live guest version therefore remains intact until republish changes the current snapshot.

## Owner experience

Invitation Studio → Media now has three focused surfaces:

1. Foto utama & film;
2. Galeri;
3. Musik.

Foto utama & film provides:

- cover upload/replace/remove;
- person-one portrait upload/replace/remove;
- person-two portrait upload/replace/remove;
- story image upload/replace/remove;
- per-person social links;
- YouTube Wedding Film configuration.

Premium media mutations are persisted immediately through owner-only endpoints. Ordinary editor save does not accept premium asset IDs from the browser and preserves server-owned `premiumMedia` state.

## Roselle composition

Roselle uses the new content in this priority order:

- dedicated cover → gallery image 1 fallback;
- dedicated story image → gallery image 2 fallback;
- portrait + social links inside each person profile;
- Wedding Film after the celebration/event journey and before gallery.

Wedding Film embeds YouTube using the existing `youtube-nocookie.com` parser/helper and lazy iframe loading. It never autoplays.

## Backward compatibility

If an owner does not configure J1.3 media:

- Roselle keeps the J1.2 gallery-derived cover and story treatment;
- text-only couple profiles remain valid;
- no Wedding Film section is rendered;
- all existing Aruna/Laras view-model fixtures remain compatible because the new presentation fields are additive/optional.

## Explicit non-scope

J1.3 does not add:

- gallery fullscreen lightbox;
- QRIS image support;
- provider/bank logos;
- physical gift delivery;
- template-native venue redesign;
- video file upload/transcoding;
- new guest data;
- WhatsApp automation;
- Aruna/Laras visual redesign.

Those remain later market-quality milestones.
