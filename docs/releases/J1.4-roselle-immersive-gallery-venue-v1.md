# SERAYA — J1.4 Roselle Immersive Gallery & Venue Experience V1

## Status

Implementation candidate. Do not mark Accepted / Locked until production smoke and owner visual acceptance are complete.

## Objective

Raise Roselle's guest-facing media and venue journey from static presentation to a premium invitation experience without reopening invitation schema, persistence, public authorization, RSVP, Guestbook, media storage, or the shared event utility state machine.

## Scope

### Immersive gallery

- Preserve the existing Roselle editorial mosaic as the in-page gallery composition.
- Every gallery image becomes an explicit, keyboard-focusable entry into a full-screen viewer.
- Full-screen viewer includes:
  - photo counter;
  - previous / next controls;
  - Escape to close;
  - Left / Right arrow-key navigation;
  - mobile horizontal swipe navigation;
  - body scroll lock while open;
  - focus restoration to the triggering gallery item;
  - existing render-safe invitation media URLs only.
- Controls maintain a 44px minimum interaction target.
- Mobile quality gates cover 430px, 390px, and 360px.
- Reduced-motion preferences disable decorative entry motion.

### Venue experience

- Keep `TemplateEventJourneyUtility` as the canonical event behavior layer for:
  - countdown;
  - ICS download;
  - Google Calendar handoff;
  - route handoff;
  - Google Maps Embed capability;
  - livestream / recording behavior.
- Add a Roselle-only presentation layer that turns each existing utility item into a venue-led composition rather than generic utility chrome.
- When no Google Maps Embed frame is available, show a truthful map-oriented preview surface that directs the guest to the existing route action. It must not impersonate an interactive map.
- When an Embed API URL is available through the existing core helper, retain the real iframe and style it as the venue visual surface.
- No unofficial Google Maps iframe URL is introduced.

## Data and backend boundary

No migration.

No changes to:

- invitation draft schema;
- published snapshot schema;
- Supabase tables or RPCs;
- media asset lifecycle;
- public or personal authorization;
- guest link lifecycle;
- RSVP persistence;
- Guestbook persistence;
- payment / publish rules.

## Compatibility

- Roselle generic remains informational and contains no personal guest identity or response forms.
- Roselle personal keeps addressed greeting, RSVP, and Guestbook in the locked template-native journey.
- Aruna and Laras event utility implementations are untouched.
- J1.3/J1.3A dedicated cover, portraits, person socials, story media, Wedding Film, and the locked desktop couple hotfix remain preserved.

## Validation gate

Before acceptance:

1. production build / TypeScript / static generation pass;
2. generic and personal Roselle showroom return HTTP 200;
3. J1.4 root marker and gallery viewer triggers render in production;
4. generic/personal response boundary remains correct;
5. no new production runtime error/fatal cluster;
6. browser interaction evidence is collected where tooling permits;
7. interactive Google map status is reported truthfully as active only when the configured Embed API key produces a real map URL.
